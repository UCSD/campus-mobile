# TritonGPT Data Models

This directory contains the shared models used by the current AI Assistant flow in `lib/ui/ai_assistant/`, `ChatProvider`, and the TGPT services.

## What Is Here

| File | Purpose |
|------|---------|
| `chat_message.dart` | In-memory UI models for assistant/user messages, parsed related-question content, and shared citation references |
| `chat_history.dart` | Sidebar/session metadata (`ChatSessionMeta`) used by `ChatProvider` |
| `chat_session.dart` | Request/response models for `/chat/create-chat-session` |
| `chat_response.dart` | Request payload models for `/chat/send-message` |
| `chat_message_persistent.dart` | Hive model for persisted chat messages |
| `chat_message_persistent.g.dart` | Generated Hive adapter for `ChatMessagePersistent` |

## Current Runtime Flow

1. `AIAssistantView` drives the assistant screen and delegates state to `ChatProvider`.
2. `ChatProvider` creates sessions, tracks the active conversation, updates sidebar metadata, and persists chat history for signed-in users.
3. `ChatMessageStreamService` streams `/chat/send-message` responses and emits text deltas plus citation references.
4. `AssistantChatMessage` stores the raw assistant text, and `AssistantMessageContent.parse(...)` strips `[rq]` markers into a separate related-questions section before rendering.
5. `ChatMessagePersistent` stores the message history that is written to Hive for logged-in users.

## Persistence Notes

- Logged-in users get persisted sessions and message history through `ChatPersistenceService`.
- Guest sessions are kept in memory only; they are not bucketed or restored from Hive.
- Citation references are part of the in-memory assistant message model, and the UI renders them as citation chips.

## Generated Code

`chat_message_persistent.g.dart` is generated by `build_runner` and is checked into the repo. Regenerate it after changing Hive fields:

```bash
dart run build_runner build --delete-conflicting-outputs
```
